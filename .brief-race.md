# Fix task — settings changes must never drop the connection

You are in `/home/c/phonon` on branch `fix/settings-race`. Read `AGENTS.md`,
`docs/lan.md`, `docs/concurrency.md`.

## Observed failures (2026-10-17, both Pixel 7s, LAN binding)

1. `POST /settings {"api_key": "..."}` returns 200 but restarts the operator
   server, because auth mode changes.
2. A `POST /settings {"bind_address":"0.0.0.0"}` issued immediately afterwards
   returns **`http=000`** — the connection is closed with no response, and the
   change is **lost**. Retrying after the server is `ready` succeeds. This
   happened on both phones and cost real time.
3. A control request without the bearer token also returned `000` rather than
   `401`, so a client cannot tell "wrong key" from "server dead".

## Required behaviour

1. **Atomic multi-field updates.** One POST may carry `api_key` and
   `bind_address` together. Apply both, then rebind/restart once. Do not
   require the caller to sequence two requests.
2. **Never drop a control request.** While the operator server is restarting,
   requests to control endpoints must receive **503** with a JSON error and a
   `Retry-After: 1` header. A closed connection is a failure.
3. **401, not a dropped socket.** An unauthorized control request returns 401
   with a JSON error.
4. **Readiness stays honest.** No `ready` until the new listener and the backend
   are both answering (this already works; keep it).
5. **No regression** in the existing verified behaviour: unauthenticated
   non-loopback bind is refused with 400; the key is enforced on `/v1/*`; health
   stays open and leaks nothing.
